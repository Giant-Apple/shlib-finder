# 上图馆藏查询

> **非官方项目** · 与上海图书馆、豆瓣均无隶属或合作关系，仅供个人查询辅助使用。
> 项目里的馆藏数据来自公开页面，界面标识归各自所有者，见 [THIRD-PARTY.md](THIRD-PARTY.md)。

把豆瓣豆列、豆瓣「想读」和手动添加的书放在一起，查**上海图书馆及全市分馆的实时在架状态**，
按离你的距离从近到远排，在地图上标出来。自己用，数据只留在本地。

## 它做什么

- **书架**：导入豆瓣豆列和豆瓣「想读」（自动抓书名 / 作者 / 出版社 / ISBN），也能手动加书；
  三组分开放，一眼看清哪本来自豆列、哪本是想读、哪本是自己加的。两边重复的书只归豆列，想读组末尾会说明有几本重复。
  书单长的时候每组都能单独收起，收起状态重开页面还记得。
- **查馆藏**：按 ISBN 查上图 + 全部分馆的逐册状态——在架 / 已借出、库室、索书号、借阅类型；同一本书的多个版本可以先选版本再查。
- **按距离排**：479 个网点（馆、服务点）带地址、电话、开放时间；离你最近的在最上面，10 公里内还会算一条骑行时间。
- **地图**：结果编号和地图标记一一对应，点标记看馆、点列表看图钉，滚轮无级缩放。
- **馆评分**：馆名右边一枚赞和净额——赞 / 不喜欢说的是你对这家馆的喜爱程度，和具体哪本书无关。
  数字要等至少 2 台不同设备赞过才出现，本地版只显示不提交；投是在浏览器扩展里。
- **手机**：同一 Wi-Fi 下手机浏览器打开就能用，不用装 App；手机端只读，改配置还是回电脑。
- **浏览器扩展**：不想开本地服务、只想在豆瓣页面上顺手看一眼这本书上海谁家有，
  装 [Microsoft Edge 加载项](https://microsoftedge.microsoft.com/addons/detail/%E4%B8%8A%E5%9B%BE%E9%A6%86%E8%97%8F%E6%9F%A5%E8%AF%A2/kpdbanjmlkfdaebckkjojfbaheojmjok)
  里的侧边栏扩展「上图馆藏查询」（项目页 [shlib-finder-extension](https://github.com/Giant-Apple/shlib-finder-extension)）。
  Windows、macOS、Linux 都能装，不用 Python 和本地服务。
  它没有书架、书单和地图，跟本地版各查各的，互不同步。

## 快速开始

### 打包版（Windows，免装 Python）

1. 在 [GitHub 项目主页](https://github.com/Giant-Apple/shlib-finder) 右侧打开 **Releases**，下载 `shlib-finder-v<版本>.zip`（包里自带 Python）。
2. 解压到任意目录，得到一个 `shlib-finder-<版本>` 文件夹，双击里面的 `start-server.bat`，浏览器会自动打开 <http://127.0.0.1:8765/>。
3. 用完关掉命令行窗口就是停止；想重开双击 `restart-server.bat`。

升级：把新包解压到旁边，再将旧目录里的 `config.json` 和 `data` 文件夹复制过去，
书单、地图 Key 和查过的结果就都在。

打包版只有 Windows。macOS / Linux 用下面的源码方式；只想查馆藏的话也可以直接装上面的浏览器扩展。

### 源码方式

需要 Python 3.9 或更高，不用装任何第三方库。

- **Windows**：双击 `start-server.bat`。
- **macOS / Linux**：

  ```bash
  git clone https://github.com/Giant-Apple/shlib-finder.git
  cd shlib-finder
  ./start-server.sh
  ```

源码方式下，Windows 和 macOS / Linux 都是把服务起在 8765，再自动打开浏览器；日志在 `data/server.log`。
也可以 `python3 web/server.py` 前台运行，在终端看到全部输出。
改过配置或代码要重启：`restart-server.sh` / `restart-server.bat`，或设置面板里的「重启服务」。

## 第一次打开要做什么

1. **设置位置**（可选，默认人民广场）。手输的地址只认上海境内，别的城市会明确拒绝，
   不会悄悄落到别的省市同名地点。
2. **填高德 Key**（可选，不填也能查馆藏）。
3. **填豆瓣地址**（可选）：豆列和「想读」各一格，只填一个也可以，都不填就只剩手动加书。
   想读页要在豆瓣设为公开。
4. **想用手机**（可选）：设置里打开「从其他设备访问」，面板会给出局域网地址和二维码。

这几项都在设置面板里填。不想用面板也行：照 [`config.example.json`](config.example.json)
的结构写一份 `config.json` 放在根目录；不建这个文件也能跑，全部走默认值。

### 两把高德 Key，别搞混

都到 [高德开放平台](https://lbs.amap.com/) 申请，**选错类型对应的功能就是不出结果**：

| 设置里的位置 | Key 类型 | 用来做什么 | 不填的后果 |
|---|---|---|---|
| 地址与距离 | **Web 服务** | 地址转坐标、骑行时间 | 手输地址转不了坐标，没有骑行时间 |
| 地图背景 | **Web 端（JS API）** | 结果区后面那张地图 | 没有地图；2021-12 之后申请的还要再填「安全密钥」 |

- 骑行只认高德。配成腾讯 Key（[lbs.qq.com](https://lbs.qq.com/)）时只能地址转坐标，
  骑行时间不显示，也不报错。
- Key 不要提交到仓库：在设置面板里填，只写进本机的 `config.json`。

## 数据从哪来

| 内容 | 来源 |
|---|---|
| 书单（书名 / 作者 / 出版社 / ISBN） | 豆瓣豆列页面、豆瓣「想读」页面及其条目页 |
| 这本书的其他版本 + 各自 ISBN | 豆瓣详情页的「这本书的其他版本」区块，逐条进版本页取 ISBN |
| 只输书名加书时的候选版本 | 上图书目检索 |
| 逐册在架状态（馆 → 库室 → 每册） | 上图的馆藏页 |
| 479 个网点的名称 / 地址 / 电话 / 开放时间 | 上图公开页面内嵌的网点信息 |
| 网点经纬度 | 高德 / 腾讯地理编码（上图不提供坐标） |
| 馆评分的净额 | 本项目的公开聚合结果（只含净额 ≥2、至少 2 台不同设备赞过的网点） |

[`data/libraries.json`](data/libraries.json)（479 个网点，188 KB）是仓库里唯一带成品数据的文件，随仓库分发是为了省掉几百次地理编码请求。字段来源、坐标口径和怎么合规使用写在 [THIRD-PARTY.md](THIRD-PARTY.md) 里：名称 / 地址 / 电话 / 开放时间是公开信息，坐标是地理编码服务的产出，本项目按**非商业用途**分发，其他用途请自行换成合规数据源重算。

其余的（书单缓存、馆藏缓存、版本清单缓存、封面、坐标缓存）都只生成在这台机器上，不上传到任何地方。

抓取都在服务端做，并且做了限流：够自己查书用，不会把别人的网站打满。

## 隐私与安全

- 默认**只监听 `127.0.0.1`**，同一网段的其他设备也连不上；要开手机访问必须手动打开开关。
- 打开后**局域网设备只读**：能查书、看结果，改不了设置。
- 改配置、重启这类写操作只接受本机页面发来的请求，其他来源一律 403。
- 地图 Key 只发给本机页面，局域网设备看不到完整 Key。
- 豆瓣想读地址里带着账号 ID，和豆列地址一样只留在本机，局域网设备拿不到。
- 本地版对「馆评分」只读：打开页面时拉一次公开的聚合结果，不提交、不带书籍或位置；
  读不到就不显示。
- 没有账号、没有遥测、没有外部上报：你的书单、位置和查询都不发往本项目。
  对外只有两件事：设置里点「检查更新」时查 GitHub 上的最新版本号；打开页面时向馆评分
  端点拉一次公开的聚合结果（不提交任何内容）。

细节和漏洞报告方式见 [SECURITY.md](SECURITY.md)。

## 已知限制

- **一个 ISBN 只代表一个版本**，不同版次 / 译者的馆藏分布可能完全不同，先选对版本再查。
- **可借数是抓取那一刻的快照**，出发前点一次「重新查询」，以结果区标出的数据时间为准。
- **接口是页面接口，不是承诺的 API**，上图或豆瓣改版就可能失效；馆藏有 12 小时缓存，
  「本书其他版本」的清单有 30 天，结果区会标出数据时间。
- **豆瓣想读页必须是公开的**；设成「仅自己可见」时会明确提示，不会显示成空列表。
  想读一页 15 本，和豆列一样分批加载。
- **节假日只做提醒、不做硬判断**，实际开馆时间以各馆公告为准。
- **坐标不保证逐条准确**：429/479 个网点有坐标，其余显示「距离未知」。
